# 云同步测试指南

## 测试目标

验证新的云同步逻辑是否按照第一性原理正确工作。

---

## 核心原则验证

### ✅ 已登录用户：云端是真相之源
### ✅ 未登录用户：本地是真相之源

---

## 测试场景

### 场景1：已登录用户清除本地存储

**目的**：验证云端数据恢复功能

**步骤**：
1. 确保已登录状态
2. 打开浏览器开发者工具 → Application → Local Storage
3. 清除所有 `pattr_*` 开头的键
4. 刷新页面（F5）

**预期结果**：
```
控制台输出：
[App] ========== 应用启动 ==========
[App] 认证状态: 已登录
[App] 用户已登录，从云端加载数据...
[App] 云端数据加载成功
[App] 数据加载完成:
  - 工作区: X
  - 项目: X
  - 作品: X
[App] 最终状态:
  - 活跃工作区: XXX
  - 活跃项目: XXX
[App] ========== 应用启动完成 ==========
```

**验证点**：
- ✅ 页面显示云端的工作区、项目、作品
- ✅ 数据完整恢复
- ✅ 不会创建新的默认工作区

---

**目的**：验证本地数据创建功能

**步骤**：
1. 确保未登录状态（或使用隐身模式）
2. 打开应用

**预期结果**：

**验证点**：
- ✅ 本地数据上传到云端
- ✅ 页面数据不变（仍显示本地数据）

### 场景7：数据冲突（云端优先）

1. 设备A：登录，创建工作区"A"

**预期结果（设备A）**：

**验证点**：
- ✅ 设备A看到工作区"B"（云端最新数据）

- ✅ 云端优先策略生效

## 调试技巧

### 查看本地存储

```javascript
// 在浏览器控制台运行
console.log('工作区:', localStorage.getItem('pattr_workspaces'))
console.log('项目:', localStorage.getItem('pattr_projects'))
console.log('作品:', localStorage.getItem('pattr_tracks'))
console.log('活跃工作区:', localStorage.getItem('pattr_active_workspace'))
console.log('活跃项目:', localStorage.getItem('pattr_active_project'))
```

### 手动触发同步

```javascript
// 在浏览器控制台运行
const { useCloudSyncStore } = window.$pinia.stores
const cloudSyncStore = useCloudSyncStore()

// 上传到云端
await cloudSyncStore.syncToCloud()

// 从云端下载
await cloudSyncStore.loadFromCloud()
```

### 清除本地数据

```javascript
// 在浏览器控制台运行
localStorage.removeItem('pattr_workspaces')
localStorage.removeItem('pattr_projects')
localStorage.removeItem('pattr_tracks')
localStorage.removeItem('pattr_active_workspace')
localStorage.removeItem('pattr_active_project')
location.reload()
```

### 查看云端数据

1. 打开 Firebase Console
2. 进入 Firestore Database
3. 查看 `users/{userId}/workspaces`、`projects`、`tracks` 集合

## 常见问题排查

### 问题1：清除本地存储后数据没有恢复

**可能原因**：
1. 云端确实没有数据（首次使用）
2. Firestore 权限问题
3. 网络问题

**排查步骤**：
1. 检查控制台是否有错误
2. 检查 Firebase Console 是否有数据
3. 检查 Firestore 权限规则

### 问题2：登录后看不到其他设备的数据

**可能原因**：
1. 其他设备没有上传数据
2. 使用了不同的账号
3. 数据同步失败

**排查步骤**：
1. 确认使用同一账号
2. 在其他设备检查是否有上传成功的日志
3. 检查 Firebase Console 数据

### 问题3：数据被意外覆盖

**原因**：
- 这是预期行为，云端优先策略

**解决**：
- 登录前导出本地数据（Header → 导出数据）
- 登录后导入数据
