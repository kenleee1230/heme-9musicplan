## [3.0.0] - 2025-12-11

### 🔧 修复

#### 云同步逻辑重构 (2025-12-11 最新)
- **第一性原理设计**: 重新设计云同步逻辑，明确数据真相之源
  - 已登录用户：云端是唯一真相之源，本地是缓存
  - 未登录用户：本地是唯一真相之源
- **清除本地存储恢复**: 已登录用户清除本地存储后，自动从云端恢复数据
- **登录时智能同步**: 
  - 云端有数据 → 下载并覆盖本地
  - 云端无数据 → 上传本地数据到云端
- **详细日志**: 添加清晰的控制台日志，便于调试和理解数据流
- **文档完善**: 新增 `CLOUD_SYNC_DESIGN.md` 和 `CLOUD_SYNC_TEST.md`

### 🎉 重大更新

#### 工作流步骤完整修复 (2025-12-11 最终修复)
- **问题修复**: 补全了所有6个项目模板和对应的工作流模板（之前只有3个）
- **项目类型专用步骤**: 每个项目类型现在有专门设计的默认步骤列表
  - 新手音乐人计划：13步完整流程（含曲风研究和审核）
  - 专业音乐人：9步高效流程（跳过前期研究）
  - 单曲制作：11步精细流程（注重质量和细节）
  - EP制作：9步平衡流程（效率与质量兼顾）
  - 专辑制作：10步专业流程（强调整体性）
  - 混音项目：11步专业流程（专注混音和母带）
- **智能工作流选择**: 根据项目类型自动应用最合适的步骤
- **完全可自定义**: 用户仍可修改、添加、删除任何步骤
- **向后兼容**: 现有作品保持原有步骤不变
- **全局考虑**: 确保 `constants.js` 包含完整的模板定义，`SongModal.vue` 正确读取

### 🎉 重大更新

#### 产品重塑
- **品牌更新**: 从 "let'sgetpattern" 更名为 "Pattr"
- **定位调整**: 从"180天音乐计划"转型为通用音乐创作项目管理系统

#### 核心架构重构
- **多层级数据模型**: 工作区 → 项目 → 作品
  - 支持创建多个工作区（个人、客户、实验等）
  - 每个工作区可包含多个项目
  - 灵活的项目配置（截止日期、目标数量、每日工作时长）
- **自定义工作流**: 可自定义作品创作步骤
- **项目模板**: 预设的项目配置模板

### ✨ 新增功能

#### 数据管理
- **完整的导入导出**: 支持工作区、项目、作品的完整备份
- **智能数据合并**: 基于更新时间的冲突解决
- **云端同步**: Firebase 云端数据同步（自动备份）
- **数据迁移**: 自动迁移旧版本数据到新结构

#### 项目管理
- **工作区管理**: 创建、编辑、删除、切换工作区
- **项目管理**: 创建、编辑、删除、切换项目
- **项目设置**: 自定义开始日期、截止日期、目标数量、每日工作时长
- **项目模板**: 180天音乐计划、专辑制作、单曲发行等预设模板

#### 用户体验
- **选择器优化**: 工作区和项目选择器，支持快速切换
- **状态持久化**: 记住上次选中的工作区和项目
- **自动切换**: 切换工作区时自动选择第一个项目
- **空状态提示**: 无数据时显示友好的空状态提示

- **依赖更新**: 修复 13 个中等严重性安全漏洞

### ⚠️ 破坏性变更

#### 数据结构变更
- 从单一 `songs` 数据迁移到 `workspaces` + `projects` + `tracks`
- 自动迁移脚本确保向后兼容
- 旧数据会自动迁移到"我的工作区 → 180天音乐计划"项目下

#### API 变更
- `useSongsStore` 部分功能迁移到 `useTracksStore`
- `useSettingsStore` 功能分散到各个项目设置中
- 导入导出 API 从只支持 tracks 升级为支持完整数据

### 🔄 迁移指南

#### 自动迁移
首次登录时会自动执行数据迁移：
1. 检测旧版本数据（`musicplan_songs`）
2. 创建默认工作区"我的工作区"
3. 创建默认项目"180天音乐计划"
4. 迁移所有歌曲到新结构
5. 保留所有计时记录和任务状态

#### 手动操作
如果遇到数据问题：
1. 导出旧数据备份（如果可能）
2. 清除浏览器 localStorage
3. 刷新页面触发重新迁移
4. 或使用 `fix-display.html` 工具手动修复
